Homework Part I: introduction to Docker

In this order: (1) Terminal Lab 1 on your own laptop, (2) the Docker Hub tour below, (3) 50 steps of your current FreeCodeCamp certification.

1 · Docker works on your laptop

  1. Install Docker: Mac · Windows · Linux. On Mac and Windows, open Docker Desktop and wait until it's running.
  2. Check it: 
    docker version
docker run --rm hello-world
    You need a Server section and "Hello from Docker!".

    If this breaks: "Cannot connect to the Docker daemon" = Docker Desktop isn't running. More fixes in Terminal Lab 1.

  3. Do every step of Terminal Lab 1, until this prints Python 3.12: 
    docker run --rm python:3.12-slim python --version

2 · Docker Hub tour: node

  1. Open hub.docker.com/_/node. Find: the Official Image badge, the Tags tab, a -slim or -alpine tag and its size, and the pull command.
  2. Pick a pinned, small tag (for example node:22-alpine) and run Node without installing it: 
    docker run --rm node:22-alpine node --version
  3. Then answer for yourself: why node:22-alpine and not node:latest? (Lecture 1, "latest ≠ stable".)

Homework Part II: Docker Fundamentals

In this order: (1) the Docker Fundamentals assignment: Tasks 1–4 and the resource checklist, steps 3–6 below, (2) 50 steps of your current FreeCodeCamp certification. Assignments go top to bottom: each task is a little harder.

3 · Set up the folders

  1. Read the assignment's README. Then make its suggested folder structure: 
    mkdir docker-assignment
cd docker-assignment
mkdir task-1-hello task-2-file-read task-3-env-vars task-4-script
git init
  2. Each task gets its own Dockerfile. Build from inside the task's folder, and always run with --rm.

4 · Tasks 1–4

  1. Task 1, one-off command: like hello-docker (Lab 2, steps 1–2), with your own message. Run with --rm, then docker ps -a shows no stopped container.
  2. Task 2, read a file: like file-demo (Lab 2, step 3): WORKDIR, COPY, print it.
  3. Task 3, environment variables: ENV NAME="value" sets one. Printing it needs a shell, because the list form of CMD doesn't swap variables in: CMD ["echo", "$NAME"] prints $NAME. Stretch: override it with docker run --rm -e NAME="other" your-image.
  4. Task 4, a script: COPY a .sh (base alpine) or .py (base python:3.12-slim) script in, and run it with its interpreter (sh or python).

    If this breaks: exec: "./hello.sh": permission denied = the script isn't executable. Run it as sh hello.sh, or chmod +x it before you build.

5 · The resource checklist

  1. Show each one in your terminal: docker ps · docker ps -a · docker rm a stopped container · docker images · docker rmi an unused image.
  2. Answer in a README.md in docker-assignment/:
    • Why don't stopped containers appear with docker ps?
    • Why can't an image be deleted if a container depends on it?
    • What does the --rm flag prevent?

6 · Commit and push

  1. Create an empty repo called docker-assignment on GitHub (no README), then: 
    git add -A
git commit -m "Docker fundamentals: tasks 1-4 and checklist"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/docker-assignment.git
git push -u origin main
    Or ask Claude (in docker-assignment/): 
    Run git status and show me the list of files. Then suggest a commit message for my Docker fundamentals tasks and wait for my approval. After I approve, commit, and push to https://github.com/YOUR-USERNAME/docker-assignment.git on the main branch.
    Claude asks before each git command. Read the file list before you say yes.

    If this breaks: "remote origin already exists" → git remote set-url origin <url>. "src refspec main does not match any" → you haven't committed yet.

  2. Submit the repo link the way your instructor asks.
