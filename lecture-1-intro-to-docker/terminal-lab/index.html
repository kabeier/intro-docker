Terminal Lab 1: your first containers

Type along with Lecture 1. Every command has a Copy button, and every step shows what you should see. Your IDs, names and version numbers may differ a little; that's normal.

In classSteps 1–4 follow the slides. About 15 minutes of typing. Something broke?Jump to the table at the bottom.

Before you start

  1. Install Docker for your OS: Mac · Windows (Docker Desktop, with WSL 2) · Linux (Docker Engine).
  2. Mac and Windows: open Docker Desktop and wait until it says the engine is running. Docker only works while it runs.
  3. Open a terminal: Terminal on Mac, PowerShell or Git Bash on Windows, your usual terminal on Linux.

1 · Is Docker working?

docker version

You should see two sections:

Client: …
 Version:           29.x
Server: …                      ← the Docker Engine (the background service)
 Engine:
  Version:          29.x
docker run hello-world

You should see:

Unable to find image 'hello-world:latest' locally     ← not an error: it downloads it
latest: Pulling from library/hello-world
…
Hello from Docker!
This message shows that your installation appears to be working correctly.

Read Docker's 4 numbered steps under that message: client → daemon → pulled from Docker Hub → created a container → output to your terminal. That's the whole lecture.

2 · Step inside a container

Which operating system is inside an alpine container?

docker run --rm alpine cat /etc/os-release
NAME="Alpine Linux"
ID=alpine
VERSION_ID=3.24.2           ← a tiny Linux, even on a Mac or Windows laptop

Now open a shell inside it. -it = let me type into it. --rm = delete the container when I leave.

docker run -it --rm alpine sh

The prompt changes to / #. You're inside. Type these one at a time:

whoami
ls /
ps
exit
/ # whoami
root
/ # ls /
bin    dev    etc    home   lib    media  mnt    opt    proc   root   run    sbin   srv    sys    tmp    usr    var
/ # ps
PID   USER     TIME  COMMAND
    1 root      0:00 sh          ← the container IS this process
    7 root      0:00 ps
/ # exit

Only 2 processes. Your laptop runs hundreds. A container is an isolated process, not a mini computer.

3 · Pull from Docker Hub, compare sizes

  1. Open hub.docker.com/_/python. Find the Docker Official Image badge, the Tags tab, the sizes, and the pull command.
  2. Pull two small versions of the same Python (about 175 MB together): 
    docker pull python:3.12-slim
docker pull python:3.12-alpine
  3. List the images on your machine: 
    docker images
    IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
alpine:latest        320994c3b997       8.42MB             0B
hello-world:latest   e2ac70e7319a       10.1kB             0B
python:3.12-alpine   979e5a8a5684       55.2MB             0B
python:3.12-slim     df18428df8a0        119MB             0B
    Older Docker shows REPOSITORY TAG IMAGE ID CREATED SIZE instead: same information. For comparison, the full python:3.12 is 1.11 GB. Don't pull it on class Wi-Fi.

4 · The same Python on every laptop

Your laptop's Python (Windows: python --version):

python3 --version

The container's Python:

docker run --rm python:3.12-slim python --version
Python 3.12.15          ← the same for everyone in the class

A real Python you never installed. exit() leaves it:

docker run -it --rm python:3.12-slim python
>>> print("hello from a container")
hello from a container
>>> exit()

Why not just docker run python? It pulls python:latest (about 1.1 GB), then prints nothing and exits: without -it there's no terminal for Python to talk to. Pin a small tag, and add -it when you want to type.

Check: you're done when…

  1. docker version shows a Server section
  2. docker run hello-world prints "Hello from Docker!"
  3. docker images lists alpine and python:3.12-slim
  4. docker run --rm python:3.12-slim python --version prints Python 3.12
  5. docker ps -a doesn't list any alpine or python containers (thanks to --rm). It does list hello-world: we ran it without --rm. Lecture 2 cleans that up.

When something breaks

You seeIt meansFix
Cannot connect to the Docker daemon, or no Server sectionThe Docker Engine isn't runningMac/Windows: open Docker Desktop and wait. Linux: sudo systemctl start docker
docker: command not foundDocker isn't installed, or the terminal was open before the installInstall it, then open a new terminal
permission denied … docker.sock (Linux)Your user isn't in the docker groupsudo usermod -aG docker $USER, then log out and in
Docker Desktop on Windows asks for WSLDocker Desktop needs WSL 2PowerShell as admin: wsl --install, restart
the input device is not a TTY (Git Bash)Git Bash needs help with -itPut winpty in front: winpty docker run -it --rm alpine sh. Or use PowerShell
python3: command not foundNo Python on your laptopThat's fine, and it's the point: the container has it
Pull is very slowEveryone is downloading at oncePull only python:3.12-alpine (smallest), or finish at home
