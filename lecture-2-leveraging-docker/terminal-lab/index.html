Terminal Lab 2: build your own image

Type along with Lecture 2. You write files in your editor and run commands in your terminal. Container names and IDs are random, so yours will differ: always use the ones your terminal shows.

In classSteps 1–8 follow the slides. About 25 minutes of typing. Something broke?Jump to the table at the bottom.

Before you start

  1. docker run --rm hello-world works (Terminal Lab 1, step 1).
  2. Make a folder and open it in your editor: 
    mkdir docker-lecture
cd docker-lecture
code .
    No code command? Open the folder from your editor's File menu.
  3. Windows: use Git Bash or WSL for step 8 (run.sh). PowerShell is fine for steps 1–7.

1 · Your first Dockerfile

In the editor, create a file named exactly Dockerfile: capital D, no extension.

FROM alpine:latest
CMD ["echo", "hello world!"]
  • FROM: start from an image published on Docker Hub (Docker pulls it).
  • CMD: the command that runs when the container starts. A list of strings. Only one per Dockerfile.

2 · Build it, find it, run it

The dot at the end means "the Dockerfile in this folder". Don't forget it.

docker build -t hello-docker .
#4 [1/1] FROM docker.io/library/alpine:latest
#5 exporting to image
#5 naming to docker.io/library/hello-docker done
docker images
IMAGE                 ID             DISK USAGE   CONTENT SIZE   EXTRA
hello-docker:latest   2a10af81544d       8.42MB             0B
…
docker run hello-docker
hello world!

Dockerfile → build → image → run → container. That's the whole workflow.

3 · Put a file inside the image

  1. Create message.txt next to the Dockerfile: 
    Hello from inside the container.
  2. Replace the whole Dockerfile with: 
    FROM alpine:latest
WORKDIR /app
COPY message.txt /app/message.txt
CMD ["cat", "/app/message.txt"]
    WORKDIR /app makes and enters /app inside the image. COPY takes a file from your folder into the image. (COPY . /app/ copies everything.)
  3. Build it under a new name, so hello-docker isn't overwritten, then run it: 
    docker build -t file-demo .
docker run file-demo
    #6 [2/3] WORKDIR /app
#7 [3/3] COPY message.txt /app/message.txt
…
Hello from inside the container.

4 · Look inside your own image

Adding sh at the end replaces the CMD for this one run:

docker run -it --rm file-demo sh
pwd
ls
cat message.txt
exit
/app # pwd
/app                     ← WORKDIR
/app # ls
message.txt              ← COPY
/app # cat message.txt
Hello from inside the container.
/app # exit

5 · Where did my containers go?

  1. Running containers only: 
    docker ps
    CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES       ← empty
  2. All containers, stopped ones too: 
    docker ps -a
    CONTAINER ID   IMAGE          COMMAND                  CREATED         STATUS                     NAMES
2c35db8c8953   file-demo      "cat /app/message.txt"   1 minute ago    Exited (0) 1 minute ago    affectionate_shaw
a239a14bf944   hello-docker   "echo 'hello world!'"    3 minutes ago   Exited (0) 3 minutes ago   stupefied_blackburn
    You may also see a hello-world container from Lab 1. Your names are different: Docker picks them at random.
  3. Remove the stopped hello-docker container. Use your name (Tab completes it): 
    docker rm YOUR_CONTAINER_NAME
  4. Start a container that keeps running for 5 minutes (-d = in the background), and try to remove it: 
    docker run -d --name sleeper hello-docker sleep 300
docker ps
docker rm sleeper
    Error response from daemon: cannot remove container "sleeper": container is running: stop the container before removing or force remove
  5. Force it (stop + remove in one step): 
    docker rm -f sleeper
  6. Never make a mess in the first place: --rm deletes the container as soon as it exits. 
    docker run --rm hello-docker
docker ps -a
    No new container in the list.

6 · Why won't my image delete?

  1. Try to delete file-demo while its stopped container still exists: 
    docker rmi file-demo
    Error response from daemon: conflict: unable to remove repository reference "file-demo" (must force) - container 2c35db8c8953 is using its referenced image b350f29a4f26
  2. Containers depend on images. Remove the container first (your name from docker ps -a), then the image: 
    docker rm YOUR_FILE_DEMO_CONTAINER
docker rmi file-demo
docker images
    Untagged: file-demo:latest
Deleted: sha256:b350f29a4f26…

Same tag twice? docker build -t file-demo . again moves the name to the new image. The old image stays, untagged, until nothing uses it. (Docker 29 hides untagged images from docker images; older versions show them as <none>.)

7 · Edit on your laptop, no rebuild (bind mount)

  1. Rebuild file-demo (we deleted it in step 6): 
    docker build -t file-demo .
  2. In the editor, change message.txt to Edited on my laptop. and save.
  3. Run it the normal way. You get the old text: COPY froze it at build time. 
    docker run --rm file-demo
    Hello from inside the container.
  4. Now lend the container your folder with -v (your folder → /app):

    Mac · Linux · WSL

    docker run --rm -v "$PWD":/app file-demo

    PowerShell

    docker run --rm -v "${PWD}:/app" file-demo
    Git Bash: MSYS_NO_PATHCONV=1 docker run --rm -v "$PWD":/app file-demo 
    Edited on my laptop.        ← live, no rebuild

8 · Automate it: run.sh

  1. Create run.sh next to the Dockerfile: 
    #!/usr/bin/env bash
set -e
# variables you may update to target the correct file
IMAGE_NAME="lecture2-demo"
CONTAINER_NAME="lecture2-container"
# this will rebuild the image within the docker engine
echo "Building image: $IMAGE_NAME"
docker build -t "$IMAGE_NAME" .
# this will run the container and automatically remove it upon completion
echo "Running container with bind mount..."
docker run --rm --name "$CONTAINER_NAME" "$IMAGE_NAME"
  2. Try to run it: 
    ./run.sh
    bash: ./run.sh: Permission denied       ← a new file isn't allowed to run yet
  3. Make it executable, then run it again: 
    chmod +x run.sh
./run.sh
    Building image: lecture2-demo
…
Running container with bind mount...
Edited on my laptop.
  4. docker ps -a: no lecture2-container, thanks to --rm.

Windows: run run.sh in Git Bash or WSL. PowerShell and Command Prompt can't run it. Stretch: add -v "$PWD":/app to the docker run line, so edits to message.txt show without a rebuild.

Clean up everything from today

Check what's there first, then remove the containers, then the images:

docker ps -a
docker rm YOUR_LEFTOVER_CONTAINER_NAMES
docker rmi hello-docker file-demo lecture2-demo

Keep alpine: the homework uses it.
